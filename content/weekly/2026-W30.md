## Highlights

### Property-based testing: error reporting, and a backlog clear-out

Error reporting was the theme. Validation error messages in the test-report
summary merged
([#77](https://github.com/input-output-hk/sc-testing-tools/pull/77)) and were
then reverted the same week
([#79](https://github.com/input-output-hk/sc-testing-tools/pull/79)); separately,
error messages now reach the CLI output when running threat models
([#82](https://github.com/input-output-hk/sc-testing-tools/pull/82)). A change to
how nullability is specified in the JSON schema went up for review
([#78](https://github.com/input-output-hk/sc-testing-tools/pull/78)), with JSON
support for the state
([#81](https://github.com/input-output-hk/sc-testing-tools/issues/81)) and
turning threat-model parameters into a `Gen a`
([#80](https://github.com/input-output-hk/sc-testing-tools/issues/80)) filed
behind it. Five older issues closed, including the two VS Code proof-of-concept
tickets ([#51](https://github.com/input-output-hk/sc-testing-tools/issues/51),
[#52](https://github.com/input-output-hk/sc-testing-tools/issues/52)) and
per-contract coverage separation
([#32](https://github.com/input-output-hk/sc-testing-tools/issues/32)), faster
in-file test identification
([#63](https://github.com/input-output-hk/sc-testing-tools/issues/63)) and
richer transaction-error output
([#72](https://github.com/input-output-hk/sc-testing-tools/issues/72)). In the
extension itself, coverage moved into the test store
([#15](https://github.com/input-output-hk/sc-testing-tools-vs-extension/pull/15))
and a non-zero exit code is no longer treated as an error
([#14](https://github.com/input-output-hk/sc-testing-tools-vs-extension/pull/14)).

### Blaster: the Data codec, audited from outside

PlutusCoreBlaster's CBOR handling got a careful external pass from @geofflittle,
who reported that the Data codec disagrees with `serialiseData` on empty
collections, empty bytestrings and negative-bignum decode
([#22](https://github.com/input-output-hk/PlutusCoreBlaster/issues/22)) and
whose fix merged the same week
([#23](https://github.com/input-output-hk/PlutusCoreBlaster/pull/23)) — plus a
follow-up accepting indefinite-length CBOR maps and constructor wrappers on
decode ([#25](https://github.com/input-output-hk/PlutusCoreBlaster/pull/25)) and
the open design question of whether the decoder should match `Data.hs` or stay
spec-faithful
([#24](https://github.com/input-output-hk/PlutusCoreBlaster/issues/24)). Thanks
for the thoroughness. The de Bruijn index implementation for the CEK machine
also merged ([#21](https://github.com/input-output-hk/PlutusCoreBlaster/pull/21)),
and a write-up of the Wanchain hack was opened in Lean-blaster
([#151](https://github.com/input-output-hk/Lean-blaster/issues/151)).
